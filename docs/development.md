# Development

Edit `src/harness.py` and the authored skills. The helper and file-contract copies under skills are generated by `scripts/build_dist.py`. Keep bundled scripts in the Python standard library and tests outside installed skills.

| Changed surface | Sufficient verification |
| --- | --- |
| Prose or links | Inspect the affected meaning, scope and references |
| Skill or manifest metadata | Validate affected metadata and inventory alignment |
| Skill behavior | Exercise realistic requests and preserve authorization boundaries |
| Helper behavior | Run mechanical regression tests for affected guarantees |
| Shared identity or persistence | Run the full helper suite |
| Helper/reference distribution | Generate copies and check byte equality |
| Discovery or installation | Check the affected installation boundary in disposable homes |

```bash
python3 -B scripts/build_dist.py
python3 -B scripts/build_dist.py --check
python3 -B -m unittest discover -s tests -v
```

The suite uses temporary projects and environments. It verifies project identity across worktrees, atomic and concurrent updates, safe path boundaries, work closure and packaging. It does not assert exact skill wording or semantic judgments.

For distribution changes:

```bash
python3 -B tests/verify_install.py
```

This check uses the pinned skills CLI and disposable host homes to install each skill selectively in copy and symlink modes for Codex and Claude Code. It removes the source before exercising installed helpers and compares the complete payload. `--cli /path/to/bin/cli.mjs` uses an existing CLI. Ordinary unit tests require neither Node nor network access.

Available host skill/plugin validators are useful for metadata checks, not runtime dependencies. State any unavailable validation rather than installing dependencies into the plugin. Before requested publication, validate the inventory and manifests, inspect the final diff and check discovery with `pnpx skills add . --list`.

Distinguish running existing checks, authoring tests and evaluating agent behavior. Add tests for uncovered mechanical guarantees or regressions, not each edited function or instruction. Do not encode exact wording, desired skill choices or semantic quality as unit assertions. Apply the user's testing/QA policy; absent cosmetic tests are not automatically a defect.

Behavioral evaluation uses realistic requests and minimal artifacts in disposable workspaces, without an expected-answer script. Follow [behavior validation](behavior-validation.md) for availability, loading, application and composition evidence. Independent evaluation requires authorization for delegation and any associated costs. Stop verification when the requested outcome and sufficient checks are established; repeat only for changed behavior, failures or concrete unresolved concerns.

Skill authoring follows the progressive-disclosure approach in [OpenAI's skill guidance](https://learn.chatgpt.com/docs/build-skills): precise descriptions, focused entrypoints and conditional references. [OpenAI's prompting guidance](https://developers.openai.com/api/docs/guides/latest-model#prompting-best-practices) informs clear scope, completion and verification boundaries. Keep operational instructions independent of model names; concrete model and effort choices belong to each temporary team.
