# Handoff

Prepare a handoff when responsibility or context is moving to another agent, or when continuity would otherwise be lost. Tailor it to the recipient's task instead of copying the whole conversation.

Preserve the objective, scope and exclusions, user constraints, accepted decisions, current state, relevant evidence and record paths, unresolved questions, and the next useful action. Include exact values or identifiers only when continuation depends on them. Separate confirmed facts from assumptions.

Write the English record through Harness tools in the relevant work. Link plans, results, and product documentation instead of reproducing them. Keep internal identifiers inside Harness.

Send a bounded message pointing to the handoff and the required action through the execution's message tools. Notification, reading, acknowledgment, and task completion are distinct. A handoff transfers context within existing authorization; it does not grant additional resources, budget, or permission.

When receiving a handoff, read what the assigned role needs, verify drift-prone facts where it matters, and request missing context from the parent. Continue accepted work rather than restarting its design unnecessarily.
